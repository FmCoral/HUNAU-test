# App UI 视觉与交互规范 · 简约数据派

> 版本 1.0 · 面向 iOS / Android / Flutter / React Native 等移动应用
>
> 核心气质：**克制、干净、透气、轻、可信**。
>
> 浅灰为底，白色承托内容；只用一抹冷静的绿；细边框、微阴影、大留白。让信息本身成为主角，装饰退到看不见。

---

## 01 · 适用范围与原则

本手册规定 App 的视觉语言、布局、组件、交互状态和交付验收，不限定业务领域。它是视觉系统，不是完整的业务流程或信息架构说明。平台系统权限弹窗、键盘、手势返回等优先遵守 iOS / Android 原生行为。

**三不原则：不要满、不要响、不要花。** 界面中性色占主导；强调色只服务关键操作、焦点和状态。优先边框，慎用阴影；层级靠排版与留白，而非彩色容器。

## 02 · 设计 Token：色彩

| Token | 浅色模式 | 深色模式 | 用途 |
|---|---|---|---|
| `color.bg` | `#f3f4f6` | `#0f1115` | 页面底色 |
| `color.surface` | `#ffffff` | `#171a21` | 卡片、弹层 |
| `color.surfaceSubtle` | `#f9fafb` | `#1c2029` | 内嵌区域 |
| `color.text` | `#111827` | `#e5e7eb` | 主要文字 |
| `color.textMuted` | `#6b7280` | `#8b93a1` | 辅助文字 |
| `color.border` | `#e5e7eb` | `#262b35` | 分割线、边框 |
| `color.brand` | `#16a34a` | `#4ade80` | 激活、强调、焦点 |
| `color.danger` | `#dc2626` | `#f87171` | 错误、危险 |
| `color.warning` | `#d97706` | `#fbbf24` | 警告 |
| `color.info` | `#0ea5e9` | `#38bdf8` | 信息 |

状态底色可用语义色约 12% 透明度，不能仅靠颜色表达状态。**5% 彩色面积**是视觉方向而非机械限制；必要的警告、图表及无障碍反馈可突破。

**可访问性优先：** 普通文字对比度至少 4.5:1，大号文字至少 3:1；图标及控件边界等必要非文本信息至少 3:1。原稿绿色 `#16a34a` 在白底上不宜直接作为小字号文字或白字实心按钮底色。建议另设 `color.brandText = #166534`（浅色模式），供小字号绿色文字使用；浅色模式实心主按钮建议 `#166534` 搭配白字，保留 `#16a34a` 作为品牌点缀。深色模式逐屏校验对比度。

## 03 · 字体与排版

使用系统字体栈；iOS 优先系统 San Francisco，Android 优先 Roboto / 系统中文字体。避免加载装饰性字体。界面字号按逻辑尺寸 pt / sp 设定，不将网页 CSS px 生搬硬套。

| 层级 | 建议字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 20 | 700 | 28 |
| 关键数字 | 22 | 700 | 28 |
| 区块标题 | 16 | 600 | 24 |
| 正文 / 表单值 | 14–16 | 400 | 22–24 |
| 辅助说明 | 12–13 | 400 | 18–20 |

尽量一屏不超过四档字号；普通正文默认 16，密集数据可用 14。不可将 11–12 作为大量重要内容的默认字号。支持系统字体放大和动态布局；金额与指标采用等宽数字特性（如平台支持）。

## 04 · 间距、圆角与层次

**间距系统：** 基础单位 4；常用 `4 / 8 / 12 / 16 / 20 / 24 / 32`。原稿的 14 / 18px 作为视觉参考，落地统一归并到 4 的倍数。页面左右内边距默认 16；卡片内边距 16；卡片间距 12–16；大区块间距 24。

**圆角系统：** 大卡片 14；内嵌容器 12；按钮与输入框 8；胶囊标签、头像 999。外层圆角通常大于内层 2；不同层级不随意新增圆角。

**边框与阴影：** 优先 1px 细边框；需要浮起时使用 `0 1px 2px rgba(0,0,0,.05)`。禁止渐变填充、玻璃拟态、重阴影、描边发光及大面积装饰纹理。

## 05 · 移动端页面骨架

1. **系统状态栏与安全区域：** 内容避让刘海、状态栏、Home Indicator 和手势导航区；滚动容器允许延伸，但可点击内容不得被遮挡。
2. **顶部导航栏：** 常规高度参考 44–56 逻辑单位，标题清晰；返回操作置于平台惯常位置；导航栏与页面采用中性背景或细分割线。
3. **内容区：** 页面底色 `color.bg`；卡片使用 `color.surface`。列表型页面可使用白色连续列表，不必每行单独做卡片。
4. **底部导航：** 仅用于 3–5 个同级主要目的地；图标配短标签，激活态使用绿色；避让底部安全区域。次要功能不要硬塞进 Tab Bar。
5. **固定操作区：** 关键 CTA 可固定底部，底部安全区另加内边距；键盘弹出时调整布局，避免遮挡表单与提交按钮。

优先单列、自然滚动布局。小屏优先缩减非必要装饰，而不是压缩触控区域。横屏、折叠屏和平板可调整列数，但 Token、排版层级及交互语义保持一致。

## 06 · 组件规范

| 组件 | 视觉与尺寸建议 | 必须覆盖的状态 |
|---|---|---|
| 主按钮 | 高 48–52；圆角 8；深绿实心，白字 | 默认、按下、禁用、加载 |
| 次按钮 | 高 44–48；白底、浅灰描边、深色字 | 默认、按下、禁用 |
| 文本按钮 | 无重底色；清晰的文字及触控区域 | 默认、按下、禁用 |
| 输入框 | 最小高 48；浅边框；标签在输入框上方 | 空、聚焦、已填、错误、禁用 |
| 搜索框 | 高 48；浅灰内嵌面；线性搜索图标 | 空、输入中、无结果 |
| 卡片 | 白底、1px 边框、14 圆角、16 内距 | 默认、可点击按下、选中 |
| 列表行 | 最小触控高 48；标题/说明分层；细分隔线 | 默认、按下、禁用 |
| 标签/徽标 | 胶囊形；淡色底 + 深色字；短文本 | 中性、成功、警告、危险 |
| 开关/复选框 | 采用平台可识别形态，绿色仅作选中态 | 开、关、禁用、焦点 |
| 弹窗/底部面板 | 白色内容面；圆角 14；简短标题和操作 | 打开、关闭、提交中、失败 |
| Toast / Snackbar | 短反馈；不遮挡关键控件；文字说明 | 成功、信息、失败 |

**触控区域：** iOS 目标尽量不小于 44×44 pt；Android 目标尽量不小于 48×48 dp。图标本身可保持约 16–20，但其点击热区必须足够大。图标统一线性、等粗、少量使用。

## 07 · 导航与交互行为

- 页面切换遵循平台返回语义；返回后尽量保留列表滚动位置、筛选条件与未提交内容。
- 同层级导航使用 Tab；局部选项使用分段控制；筛选项较多时使用独立筛选页或底部面板。
- 危险操作必须明确命名，必要时二次确认；可撤销操作优先提供撤销。
- 输入错误在字段附近显示原因及修复方式，不只使用红色边框。
- 不依赖 hover：移动端以按下、选中、聚焦、禁用等状态为主。

## 08 · 页面状态与反馈

**加载：** 优先骨架屏或局部进度反馈，避免整个页面长时间空白；提交时防止重复触发。**空状态：** 说明为什么为空，并提供明确下一步；保持简约，不需要大幅插画。**错误：** 用人能理解的语言说明失败原因，提供重试或恢复路径。**离线：** 明确网络不可用，允许查看已有内容（若业务支持）。**成功：** 以短暂文字反馈为主，必要时返回结果页。

所有异步组件应覆盖：初始、加载中、成功、无数据、失败、重试；涉及表单的还要覆盖校验错误与提交中。

## 09 · 动效与触觉反馈

普通颜色/边框过渡参考 120–200ms；面板展开、页面导航可按平台原生时长执行，不强制全部小于 200ms。缓动平稳，不做弹跳、回弹、长距离飞入或炫技旋转。尊重系统“减少动态效果”设置；重要状态变化同时提供文字或可访问性提示。触觉反馈只用于必要的确认或关键切换，不滥用。

## 10 · 深色模式

深色不是简单反色。页面使用冷调深灰 `#0f1115`，内容面 `#171a21`，内嵌面 `#1c2029`，边框 `#262b35`，文字 `#e5e7eb`。主色提亮为 `#4ade80`，但仍须核验文字与按钮对比度。图片、插图、系统栏图标、键盘主题、阴影均应分别适配。

## 11 · 图表、数据与密集信息

数据优先使用数字、标签、单位和时间范围表达；图表颜色不应成为唯一识别渠道，搭配图例、直接标签或不同线型。趋势优先简单折线或柱状，不使用强渐变与立体图。表格在手机端优先改为卡片/分组列表；确需横向滚动时明确提示，固定关键字段并避免裁切数值。金额、日期、百分比保持格式一致。

## 12 · 交付给设计与开发的约定

- 设计稿需包含浅色/深色、主要屏幕宽度、长文本、系统字体放大、键盘弹出及安全区示例。
- 组件库使用统一 Token 命名，不在页面内随意硬编码颜色、圆角和间距。
- 每个组件附默认、按下、焦点、禁用、加载、错误等适用状态。
- 图标使用统一线性图标库；图标与文字对齐；触控热区单独标注。
- 研发验收时检查：状态覆盖、系统返回、滚动、键盘、无障碍标签、触控尺寸、对比度、深色模式。

## 13 · 最终验收清单

- [ ] 页面以浅灰/白色中性色为主，绿色只强调重点
- [ ] 无渐变、玻璃拟态、重阴影与不必要的插画
- [ ] 标题、正文、辅助文字层级清晰；系统字号放大后不截断关键内容
- [ ] 间距来自统一 4pt 刻度；圆角仅使用规定层级
- [ ] 安全区域、底部导航、键盘避让和返回行为正确
- [ ] 按钮、表单、列表、弹层的状态完整
- [ ] 所有可交互元素触控热区足够大
- [ ] 文本、图标、控件边界对比度达标；状态不只靠颜色表达
- [ ] 加载、空状态、错误、离线和重试路径清晰
- [ ] 深色模式、长文本与无障碍模式已验证
- [ ] 去掉颜色后，信息层级仍然成立

---

> **最终判断：** 好的 App UI 不是把原有风格“装饰”到每个组件上，而是让所有屏幕都遵守同一套安静、专业、可用的规则。
